# Research

把模糊的调研请求变成**可溯源的结构化结论**。

## 何时使用

- 需要外部信息才能回答的问题
- 方案对比、竞品分析、技术选型
- 需要给出处、不能凭空断言的问题

## 步骤

### 1. 界定问题

- 复述问题，写出 2–4 条**明确的调研子问题**。
- 列出已知信息与需要查证的假设。

### 2. 检索

- 用 `web_search` 检索，每轮针对一个子问题。
- 对高价值来源用 `http_request` 或网页抓取工具读原文，而不是只信摘要。
- 优先一手来源（官方文档、规范、公告），其次权威媒体，最后聚合内容。

### 3. 比对与溯源

- 为每条结论标注来源链接。
- 来源冲突时并列呈现，说明分歧点，不要静默取其一。
- 区分**事实**与**推断**，推断必须显式标注。

### 4. 成文

输出结构：

```
## 结论
（3–5 条要点，直接回答）

## 依据
（每条结论对应的来源与关键原文摘录）

## 不确定项
（未能证实、来源冲突、时效性存疑的部分）

## 来源
（链接列表）
```

## 注意

- 不要编造链接、数字或引用；检索失败要如实说明。
- 时效性敏感的问题要标注信息的发布时间。
- 内容较长时先给结论再展开，不要把原文整段粘贴。
